# Шпаргалка для объяснения (сайт-портфолио)

**Как устроено в одной фразе:** все страницы статические, Next.js собирает их при `build`; единственный серверный код — отправка формы.

1. **App Router.** Папка = маршрут: `app/about/page.tsx` → `/about`. Страницы — серверные компоненты: HTML рендерится на сервере/при сборке, в браузер уходит минимум JS. Клиентский компонент один — `ContactForm` (`"use client"`), потому что у формы есть состояние.
2. **Кейсы в MDX.** Один файл = один кейс: `export const meta` (заголовок, стек, ссылки) + текст в Markdown. Список slug'ов в `lib/projects.ts` — единственный «реестр»: из него строятся `generateStaticParams` (страница на каждый кейс при сборке), сетка и sitemap. `dynamicParams = false` → неизвестный slug сразу 404, лишний файл импортировать нельзя.
3. **Форма.** `useActionState` + server action `sendContact`: валидация на сервере (клиенту доверять нельзя), honeypot — скрытое поле `website`, бот его заполняет → делаем вид, что отправили. Письмо — один `fetch` в REST API Resend, без SDK. Ключ и адрес — только в env, в браузер не попадают. Без ключей: в dev форма «работает вхолостую», в проде честно пишет «недоступна».
   - Тонкость React 19: после action форма сбрасывается, поэтому при ошибке сервер возвращает введённые значения, и они подставляются через `defaultValue`.
4. **SEO.** Metadata API: шаблон заголовка в `layout.tsx`, у каждой страницы свой `title/description/canonical`; кейсы — через `generateMetadata`. `opengraph-image.tsx` генерирует картинку для соцсетей, `sitemap.ts`/`robots.ts` — файлы для поисковиков.
5. **Стили.** Tailwind 4 (конфиг прямо в CSS через `@theme`), текст кейсов — плагин Typography (`prose`).
6. **Деплой.** На Vercel: импорт репо + 4 переменные окружения. Ни базы, ни своего сервера.

**Частые вопросы клиента:**
- *Почему не CMS?* Кейсов мало, MDX в git — бесплатно, версия каждой правки видна. CMS подключается заменой `lib/projects.ts`.
- *Как защищена форма?* Валидация на сервере, honeypot, лимиты длины, ключ только на сервере. Для большого трафика добавил бы rate limit (например, Upstash) — сейчас не нужно.
- *Почему Next.js, если опыт в Vue?* Это мой личный проект на Next.js; коммерческий опыт — Vue/Nuxt, подходы (SSR, статическая генерация, метаданные) те же.
